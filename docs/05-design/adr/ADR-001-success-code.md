# ADR-001：统一成功码为 `"0"`

- 状态：已接受（取代「文档写 `OK`」的旧口径）
- 对应裁决：`docs/4 §11 D1`
- 日期：2026-10-19 裁决 / 2026-11-02 定稿
- 决策人：成员 A + 评审组
- 关联：`docs/4 §0.3`、`§1.1`、`§1.7`、`backend/common` 的 `Result` / `ErrorCode`

## 背景

文档原先写成功码 `code:"OK"`，而 `common` 中 `Result` 实现是 `code:"0"`。两套口径同时存在会导致：
前端拦截器判断不一致；OpenAPI 示例与实现不一致；跨服务（Feign、网关错误包装）判定分叉。

## 选项

| 选项 | 说明 | 取舍 |
|---|---|---|
| A. 后端改 `OK` | 跟文档走，改 `Result` 常量与全部断言 | 前端/网关/已有测试几乎全要改，历史代码多 |
| B. 统一 `"0"` | 保持现有实现，改文档与前端拦截器 | 改动面最小；`"0"` 作为字符串码与 HTTP 200 无冲突 |
| C. 只保留 HTTP 状态 | 去掉 body 业务码 | 与 409/403 等业务细分冲突，需重设计 |

## 结论

统一 `code == "0"` 表示成功；HTTP 200 + `code != "0"` 一律按失败处理。
前端只在一处（axios 响应拦截器）判断，业务代码不得自行比较其他成功值。

## 影响

- 接口：所有 `Result<T>` 响应；OpenAPI 示例统一写 `"code": "0"`。
- 代码：`common` 的 `Result.success()` 保持不变；新增单测锁定 `code="0"`。
- 前端：响应拦截器以 `"0"` 为唯一成功值；不再兼容 `"OK"`。
- 文档：`docs/3`、`docs/4`、OpenAPI 示例同步（§11 D1 已回写）。

## 回滚方式

只涉及前后端常量与拦截器，不涉及数据库：
1. 后端 `Result` 常量改回旧值；
2. 前端拦截器同步改回；
3. 两侧必须同版本发布，否则全站报错。
不建议保留双值兼容超过一个迭代，避免长期分叉。
