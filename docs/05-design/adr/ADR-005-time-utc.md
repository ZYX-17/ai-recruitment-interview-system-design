# ADR-005：时间统一 UTC 存储、ISO 8601 输出

- 状态：已接受
- 对应裁决：`docs/4 §11 D20`
- 日期：2026-10-19 裁决 / 2026-11-02 定稿
- 决策人：成员 A + 成员 B/C
- 关联：`docs/4 §1.1`、`§5.4`、`§7.2`、`sql/02_recruit_interview.sql`

## 背景

面试排期跨时区（面试官/候选人/服务器），MySQL `DATETIME(3)` 不带时区信息。
若按服务器本地时间写入，容器时区变化、Nacos 多实例、导出报表都会产生偏移；
排期槽位（30 分钟一格）又必须用业务时区切分自然日。

## 选项

| 选项 | 说明 | 取舍 |
|---|---|---|
| A. 存服务器本地时间 | 直接写 `LocalDateTime` | 多实例/容器时区不一致时数据错乱；不可接受 |
| B. 存 UTC + 接口 ISO 8601 | 统一换算点 | 需要全局配置与前端转换；可验证 |
| C. 改 `TIMESTAMP` | 数据库自动时区 | MySQL `TIMESTAMP` 2038 上限、时区依赖会话变量，仍不稳 |

## 结论

采用 B，规则固定：

1. 数据库：所有时间列 `DATETIME(3)`，**存 UTC**；`created_at/updated_at` 由应用写 UTC，不用 `NOW()`。
2. 接口：输入输出统一 ISO 8601，带 `Z` 或显式偏移，如 `2026-10-19T02:00:00Z`。
3. 业务时区：`slot_date`（自然日/日历分组）按 `Asia/Shanghai` 计算；面试起止仍用 UTC 时刻。
4. 时间粒度：排期必须对齐 30 分钟，非对齐返回 `SYS400`（§11 裁决 2），不做自动取整。
5. 前端：只在展示层转本地时区；请求参数必须带偏移，禁止传裸 `yyyy-MM-dd HH:mm:ss`。

## 影响

- 全局配置：Jackson `spring.jackson.time-zone=UTC`、`date-format` 统一；`LocalDateTime` 序列化需自定义或统一用 `OffsetDateTime/Instant`。
- 数据访问：MyBatis 类型处理器统一；禁止在 SQL 里用 `NOW()`/`CURDATE()` 写业务时间。
- 排期（P5）：槽位计算、冲突检测、日历查询全部基于 UTC 时刻 + `Asia/Shanghai` 日界。
- Offer 过期/通知延迟：以 UTC 计算，延迟消息 `x-delay` 用毫秒差，不用本地时间差。
- 统计：日/周分组按 `Asia/Shanghai`，与展示一致。
- 测试：固定时区跑用例（`-Duser.timezone=UTC`），断言序列化字符串带 `Z`。

## 回滚方式

属于高代价决策，**不建议回滚**：
1. 若必须改口径，新增偏移列并双写一个迭代，而不是原地改历史值；
2. 历史数据订正必须脚本化、可审计、先在备份库演练；
3. 任何回滚都需新 ADR 并同步 `docs/2`、`docs/3`、`sql/`、前端时间工具。
