### 1.3 三人分工详表（v3.1 核心变更）

**分工原则**：一人一个子系统（论文主线与题目一一对应）+ 各兼一块公共底座；服务 Owner 唯一，跨服务只走契约（OpenAPI/事件），详见第 5 节。

| 成员 | 子系统（论文主线） | 后端服务 | 前端域 | 兼任 |
|---|---|---|---|---|
| **A（本人）** | 面试管理子系统 | gateway / auth(IAM) / interview / notify | — | **集成负责人**：CI/CD、契约仲裁、周五合并、应用节点部署 |
| **B（同学）** | 智能简历与人才管理子系统 | resume / file / ai-service / ai-worker / mineru-worker | — | **AI 底座与 GPU 节点负责人**：vLLM/FunASR/MinerU/ES 部署与压测 |
| **C（前端同学）** | 在线面试子系统 | room | **全部前端**（36 页 + LiveKit 房间页） | **演示负责人**：runbook、演示脚本、答辩演练 |

#### 1.3.1 成员 A —— 面试管理子系统 + 平台底座

**负责范围**：4 个 Java 服务（gateway / auth / interview / notify），**41 个端点**（auth 15 + interview 22 + notify 4），2 个 schema（recruit_auth / recruit_interview / recruit_notify），WS 不涉及。

**使用的中间件**：

| 中间件 | 在 A 范围内的用途 |
|---|---|
| Nacos 2.3.x | 注册发现 + 配置中心（鉴权/限流/状态机规则/取整规则热更） |
| Spring Cloud Gateway | 路由、JWT 验签前置、IP+用户令牌桶限流（Redis Lua）、`/internal/**` 屏蔽、traceId 生成 |
| Redis 7.2 | JWT 会话五键（`auth:refresh:*`/family/`auth:bl:{jti}`/`auth:tv`/`auth:perm`，见 4.3）、Idempotency-Key SETNX、登录失败锁定计数 |
| RabbitMQ 3.13 | 本地消息表（local_message）发件箱投递 + publisher confirms；延迟插件（Offer 过期/回访提醒）；死信队列 |
| MySQL 8.0 | iam_* 8 表 + interview 13 表 + notify 3 表，Flyway V1_0/V1_1(种子) |
| Spring Mail | SMTP 邮件通道（站内信写库；短信 Mock 适配器） |

**关键技术实现**：

1. **JWT 双令牌**：jjwt/nimbus-jose 签发 RS256；Access 2h + Refresh 7d；Refresh 轮换 + **family 重放检测**（旧 jti 重现 → 撤销整个 family）；禁用/改密递增 token_version；网关 Redis 不可达 fail-closed。
2. **动态菜单 RBAC**：iam_permission 三态（MENU/BUTTON/API）+ `/api/auth/menus` 返回树 → 前端动态注册路由；服务端 `@PreAuthorize` 权限码校验（Spring Security 方法安全）+ 权限缓存版本即时生效。
3. **数据范围**：`@DataScope` 注解 + MyBatis 拦截器按 ALL/DEPARTMENT/ASSIGNED/SELF 注入查询条件；候选人 `@OwnerCheck` 切面防水平越权。
4. **状态机**：显式流转表（`Map<状态, Map<事件, 目标态>>`）+ Service 层校验 + `version` 乐观锁 + application_stage_history 流水可回放；不用 Spring Statemachine（过重）。
5. **排期三方冲突**：schedule_slot 唯一索引兜底，同事务 INSERT 捕获 `DuplicateKeyException` → 重查占用方返回 ITV3101 冲突明细；`conflict-check` 仅体验预检；时间 30 分钟对齐契约（5.3）。
6. **评价模板版本化**：evaluation 记录 template_version，模板修改不影响历史评价；多面试官评价唯一索引防重。
7. **Offer 闭环**：confirm_token 哈希存库 + 免登录确认页 + CAS `SENT→CONFIRMED`（幂等，过期 ITV3301）；延迟消息做过期提醒。
8. **一致性**：业务表与 local_message 同事务写入 → 定时扫描投递 MQ → confirms 回执 → INIT/SENT/CONFIRMED/DEAD 状态机；消费端幂等表。
9. **可观测**：logback JSON + traceId MDC 贯穿（网关生成 → Feign 透传 → MQ 信封携带）；Actuator + Micrometer 暴露 Prometheus。

**里程碑对应（架构文档第 7 章）**：W2 鉴权底座与网关 → W3~4 岗位/投递/流程模板 → W5~6 状态机/排期冲突/评价/Offer/通知 → W9~10 纪要回写与评价草稿流转 → W11 异步面试业务表 → W12 Offer 简化审批 → W14 API 压测与排期并发测试。

#### 1.3.2 成员 B —— 智能简历与人才管理子系统 + AI 底座

**负责范围**：2 个 Java 服务（resume / file）+ **3 个 Python 工程**（ai-service / ai-worker / mineru-worker）+ ES `resume_vec` 索引，**24 个端点**（resume 14 + file 3 + ai 7），3 个 schema（recruit_resume / recruit_file / recruit_ai），GPU 节点全部容器。

**使用的中间件**：

| 中间件 | 在 B 范围内的用途 |
|---|---|
| Elasticsearch 8.13 | `resume_vec`：dense_vector 512 维 + HNSW(m=16, ef=200) + ik_max_word/ik_smart；BM25 + kNN + RRF 混合检索（6.4） |
| RabbitMQ 3.13 | 解析任务（resume.received → mineru-worker 回调）、实体抽取（resume.parse.completed → ai）、查重/合并事件消费；发件箱 |
| MinIO | 简历原件/Markdown 产物/表格 JSON 存储；file-service 预签名直传（不过网关） |
| Redis 7.2 | 解析任务状态缓存、匹配结果缓存（job/resume/prompt/model 版本键）、Embedding 幂等 |
| GPU 节点 | vLLM 8000（Qwen2.5-7B-Instruct-AWQ，guided decoding）、FunASR（ai-worker 内）、MinerU（mineru-worker 内，独立容器防 OOM） |
| MySQL 8.0 | resume 14 表 + file 1 表 + ai 8 表（ai_task/prompt_version/model_config/ai_call_log/human_review…），Flyway |

**关键技术实现**：

1. **解析流水线（题目硬约束）**：上传（file-service 校验 MIME/大小/分片）→ MinIO → `resume.received` → MinerU（PDF/Word/图片 → 结构化 Markdown + 表格 + 图注）→ 入库 → **分块**（300~500 token；表格整体独立成块、超长按行分组且重复表头；标题路径前缀 `[工作经历>腾讯>2019-2022]`）→ **BGE bge-small-zh-v1.5**（512 维，CPU <20ms/条，批量 32~64）→ ES bulk → PARSED → LLM 实体抽取。
2. **LLM 编排（ai-service，FastAPI）**：LlmRouter 四级降级（**vLLM 主 → 云端 DeepSeek/通义备 → Ollama 无 GPU 档 → 模板**）；openai SDK 统一 OpenAI 兼容端点（切档只改 base-url+model）；guided JSON Schema + **Pydantic 二次校验**（失败修复一次再失败标 FAILED）；Prompt 版本入库（变更走 PR + 回归集）；ai_call_log 审计/配额/降级次数。
3. **人岗匹配双路**：规则硬过滤（Java 自研解释器，白名单操作符，≤1s）→ ES 混合召回 top50（BM25 text^2+skills + kNN，RRF）→ LLM 精排 top20（五维：技能/经验/学历/稳定性/潜力，每维带证据；必备项未命中总分封顶）→ `final = 0.3×召回 + 0.7×LLM`；权重/参数 Nacos 热更，**消融实验 = 答辩数据**。
4. **查重去重**：SHA256 文件级 → phone_hash 精确层 → ES kNN 摘要向量相似层（阈值 0.92，正负样本定标）→ **只提示，人工确认合并**；resume_version 不覆盖旧版本。
5. **FunASR（ai-worker，供 C 的在线面试调用）**：Paraformer 流式 + fsmn-vad + ct-punc + 热词；`/ws/asr/{sessionId}` 收浏览器 PCM；BGE embedding 批量接口 `/api/v1/embed`；并发容量契约（7.2：单实例 ≥20 路）。
6. **检索兜底**：ES 挂 → Nacos `search.mode=mysql-like`（30s 生效）；emb_model 版本字段支持换 BGE-M3 时新索引+别名切换。

**里程碑**：W1 vLLM/FunASR 并发/MinerU spike → W3~4 file+解析管线+检索 → W5~6 查重/标签/硬过滤 → W7~8 FunASR 字幕链路 → W9~10 ai-service 收口（匹配/纪要/提示）→ W11 录播评分 → W12 向量去重/合并深化 → W13 AI 评测实验（F1/Top5/NDCG/CER）。

#### 1.3.3 成员 C —— 在线面试子系统 + 全部前端

**负责范围**：1 个 Java 服务（room，8 端点 + WS 协议）+ **全部前端**（单 SPA 36 页：候选人 11 / 面试官 7 / HR 14 / 管理员 4）+ LiveKit/Egress 媒体面集成；1 个 schema（recruit_room）。**注意**：C 是唯一横跨前端+后端的成员，W7~10 为峰值（A/B 按协作契约支援房间前端组件与联调）。

**使用的中间件**：

| 中间件 | 在 C 范围内的用途 |
|---|---|
| LiveKit SFU + Egress | WebRTC 媒体面（1v1/1v5 Simulcast/Dynacast）、入会令牌校验、房间合成录制 → MP4 → MinIO（S3 直写） |
| Redis 7.2 | 房间在线状态、WS 会话、ASR 短时令牌登记 |
| RabbitMQ 3.13 | room.finished / recording.completed 事件发布（Outbox）、聊天/系统事件广播辅助 |
| MinIO | 录像与防作弊证据文件；file-service 预签名回放（10min） |
| MySQL 8.0 | recruit_room 8 表（room/room_participant/room_event/record_meta/cheat_event/interview_note/chat_message/transcript_segment），Flyway |
| Nginx | WSS 反代（`/ws → room`、`/api/ai/v1/asr → ai-worker` rewrite、`livekit.<domain>` 子域名信令） |
| 前端栈 | Vue 3.4 + TypeScript + Vite 5 + Pinia + Element Plus + **livekit-client** + AudioWorklet |

**关键技术实现**：

1. **后端（room-service）**：LiveKit Java Server SDK 签发入会令牌（只授指定 room+identity+能力，TTL ≤2h，同 identity 重连顶掉旧连接）；房间状态机 `CREATED→WAITING→LIVE→FINISHED`（+CANCELED/FAILED）；Webhook **JWT 验签（Authorization Bearer，LiveKit API secret 校验）+ body sha256 校验 + 幂等**（event 表去重）；名额 `current_count` 行级原子 UPDATE 扣减/`participant_left` 归还（GREATEST 防负）+ LiveKit ListParticipants 定时对账；Egress 录制编排（start/stop，失败不阻塞面试、可重试）。
2. **WS 协议**：Spring `TextWebSocketHandler`，首帧 AUTH JWT（10s 超时关闭 4001）；type=CHAT/SUBTITLE/SYSTEM；心跳 15s/判离 30s；seq 保序去重；聊天落库后广播、字幕不回补。
3. **前端框架**：动态路由（`/api/auth/menus` + `import.meta.glob` 映射组件）；按钮 `v-permission` 权限码指令（与前端骨架 frontend/src/utils/permission.ts 统一）；axios 单例（401 挂起刷新队列 → Refresh 轮换重放）；Pinia stores（auth/task/room/notify）；任务轮询（0/2/5/10s 后每 20s，5 分钟超时）。
4. **LiveKit 客户端封装（rtc/livekit.ts）**：`joinRoom(token)` → `Room.connect(livekitUrl, token)`；1v5 网格按参与者数自适应（>4 人缩略图+主视图）；**Simulcast 低轨订阅**（群面 360p/540p，放大升轨）；屏幕共享 `setScreenShareEnabled`（同房限 1 人）；设备预检（枚举+预览+权限引导）；断线自动重连 + 弱网提示（RTT>300ms 黄条）。
5. **ASR 采集**：AudioWorklet 本地采集 16kHz/16bit/单声道 PCM（100~200ms/帧）→ WSS `/api/ai/v1/asr/{sessionId}?token=scope-asr`（5min 轮换，断线带 lastSegmentId 续传）→ 字幕侧栏虚拟滚动（环形缓冲 200 条）。
6. **防作弊埋点**：`visibilitychange`/`blur` 切屏、离屏时长采集 → cheat_event 批量上报（2s 合并去重）→ 仅展示不判定。
7. **回放/纪要**：预签名回放页（鉴权）；纪要人工复核界面（AI 草稿 → 编辑 → 确认归档）。

**里程碑**：W1 LiveKit spike（2/6 人通话+录制+手机热点跨网）→ W2 Vue 工程与登录框架 → W3~4 上传/解析状态/列表页 → W5~6 泳道看板/排期日历/评价表单 → **W7~8 room 后端 + 房间页（1v1/1v5/聊天/共享/重连）** → W9~10 录制回放/纪要复核界面 → W11 录播作答页 → W14 WebRTC 真实浏览器压测 → W15 演示排练。

## 2. 服务与数据所有权

### 2.1 数据库 schema

`recruit_auth`、`recruit_interview`、`recruit_room`、`recruit_resume`、`recruit_notify`、`recruit_file`、`recruit_ai`。gateway 无库。

规则：

- 只能写自己 schema；跨服务只存 ID + 快照，禁止跨库 JOIN/跨库写。
- 每个 schema 附 `local_message`（发件箱）与 `idempotent_consumption`（消费幂等）。
- 雪花 ID 字符串化；时间 UTC 存储、ISO 8601 输出；枚举 `VARCHAR(32)`；关键状态表 `version` 乐观锁。
- `job`/`application` 归 interview；resume 通过 `job.published/job.updated` 维护 `job_snapshot` 做匹配。
- 候选人 `person` 归 resume；interview/room 存 `person_id` + 姓名/岗位快照。

## 3. API 契约

### 3.1 通用约定

- 前缀：`/api/auth`、`/api/interview`、`/api/resume`、`/api/room`、`/api/ai`、`/api/notify`、`/api/file`；内部接口 `/internal/**` 不对外。
- 响应：`{"code":"OK","message":"success","data":{},"traceId":"...","timestamp":...}`；错误码如 `ITV3101`、`ROM4004`、`AIS5001`。
- 分页：`{list,total,pageNum,pageSize,pages}`；`pageSize ≤100`。
- ID 字符串；时间 ISO 8601；金额/年限按字段注释。
- 写操作支持 `Idempotency-Key`；更新带 `version`；非幂等 POST 不自动重试。
- 每个非公开接口必须登记权限码；菜单/按钮/API 三态一致。

## 4. 鉴权与 RBAC

### 4.1 五角色

`SUPER_ADMIN`（系统维护）、`HR_ADMIN`（招聘管理员）、`RECRUITER`（招聘专员）、`INTERVIEWER`（面试官）、`CANDIDATE`（候选人）。

- `SUPER_ADMIN` 受保护，不能删除最后一个系统管理员。
- `HR_ADMIN`/`RECRUITER` 的数据范围分别为 ALL / DEPARTMENT；`INTERVIEWER` 默认 ASSIGNED（只看被安排场次）；`CANDIDATE` 只能访问自己的数据。
- 候选人接口统一走 `/api/*/portal/**`、`/api/offer-portal/**`；网关做入口隔离，服务内再做对象级校验。

### 4.2 权限三态与数据范围

1. **菜单**：能否看到入口；`/api/auth/menus` 返回树。
2. **按钮/API 权限码**：能否调用接口；服务端 `@PreAuthorize` 或等效授权器校验。
3. **数据范围**：能看到哪些数据；`ALL / DEPARTMENT / ASSIGNED / SELF`，通过 `@OwnerCheck`/查询条件落实。

> 前端隐藏按钮只是体验，不是安全边界。

### 4.3 Token 与 Redis Key

- Access 2h + Refresh 7d；Refresh 旋转；`token_version` 撤销。
- Refresh 建议 `HttpOnly + Secure + SameSite=Strict` Cookie；若走响应体，前端不落 localStorage，并配置 CSP。
- Redis Key：

| Key | 用途 |
|---|---|
| `auth:refresh:{hash}` | Refresh 会话 |
| `auth:refresh:family:{familyId}` | 重放检测 |
| `auth:bl:{jti}` | Access 黑名单 |
| `auth:tv:{userId}` | token version |
| `auth:permver:{userId}` | 权限版本 |
| `auth:perm:{userId}:{ver}` | 角色+权限缓存 |
| `auth:rate:{scope}:{key}` | 限流 |

### 4.5 必测鉴权用例

## 5. 事件与一致性

### 5.1 事件信封

```json
{
  "eventId": "uuid",
  "eventType": "interview.scheduled",
  "eventVersion": 1,
  "occurredAt": "2026-11-02T02:00:00Z",
  "traceId": "…",
  "aggregateId": "applicationId",
  "payload": { "只带 ID 与必要快照" }
}
```

### 5.2 关键事件

| 事件 | 发布方 → 订阅方 | 用途 |
|---|---|---|
| `resume.received` / `resume.parse.completed` / `resume.parse.failed` | resume | 解析流水线 |
| `candidate.duplicated` | resume → notify | 查重提醒 |
| `job.published` / `job.updated` | interview → resume | 更新 JD 快照/匹配缓存 |
| `interview.scheduled` / `interview.cancelled` | interview → room/notify | 建房/关房/邀约 |
| `room.created` / `room.create.failed` | room → interview | 建房回执（回填 room_id）/ 建房失败重试或人工 |
| `interview.result.submitted` | interview → notify/ai | 结果通知/画像 |
| `room.finished` | room → ai/interview | 纪要/评价草稿（转写就绪） |
| `recording.completed` | room → interview/ai | 录像登记；可选补转写 |
| `offer.confirmed` | interview → notify/resume | 人才库状态 |
| `talent.followup.due` | resume → notify | 回访提醒 |
| `ai.task.failed` | ai → 业务服务 | 标记失败可重试 |
| `notification.requested` | 各服务 → notify | 统一通知请求 |

### 5.3 一致性规则

- 本地消息表 + RabbitMQ publisher confirms + 手动 ack + 死信 + 幂等消费；不引入 Seata。
- 排期：`schedule_slot` 唯一索引兜底；预检与写入同库同事务；取消物理删 slot + interview 软删。
- **时间粒度**：面试起止必须对齐 30 分钟；如允许任意分钟，预检/写槽使用统一取整规则并写进 API。
- 建房：interview 写 `ROOM_PENDING` → `interview.scheduled` → room 建房回执；失败重试，超阈值人工处理。
- 名额：`current_count` 原子更新；token 签发幂等（room+user）；未加入 token 预留 TTL；离会/房间结束/Webhook 归还；定时用 LiveKit `ListParticipants` 对账。
- AI 结果：草稿 + 人工确认后写正式状态；失败/超时可重试。

## 6. AI 服务

### 6.1 路由与边界

```
Java 业务 → ai-service（FastAPI；鉴权/配额/Prompt/降级/审计）
  → vLLM（主，Qwen2.5-7B-AWQ）→ 云端 LLM（备）→ Ollama（无 GPU）→ 模板
  → RabbitMQ → ai-worker（FunASR/BGE）
  → RabbitMQ → mineru-worker（MinerU）
```

- ai-service 不持有招聘业务主表；结果通过内部 API/事件回写。
- 所有模型调用统一 OpenAI 兼容客户端；换供应商只改 `base-url` + `model`。
- 结构化输出用 JSON Schema + 校验；失败修复一次，再失败标记任务失败。
- 简历/转写按不可信数据定界，防 Prompt Injection；AI 分数只作建议，人工确认。
- 不推断年龄/性别/婚育等岗位无关属性。

### 6.2 任务

| 任务 | 触发 | 输出 |
|---|---|---|
| 简历解析 | `resume.received` | Markdown + 结构化 JSON + chunk/embedding |
| 实体抽取 | `resume.parse.completed` | 教育/经历/技能/年限 + 置信度 |
| 人岗匹配 | resume 服务调用 | 分项分 + 证据 + 缺口 |
| 面试纪要/评价草稿 | `room.finished`（转写就绪） | 摘要 + 证据 + 建议分 + 待确认项 |
| 录播评分 | 作答齐 | 逐题分 + 证据 |
| 实时问题提示 | 转写新增 | 2~3 条追问；仅面试官可见 |

### 6.3 简历流水线

1. 上传 → file 校验/对象存储 → `resume_parse_task(PENDING)` + `resume.received`。
2. mineru-worker 解析 PDF/Word/图片 → Markdown/JSON/表格/公式/图注，写 MinIO。
3. 分块：300~500 token/块；按标题/语义切；**表格整体独立成块**，超长按行分组且重复表头；每块前缀注入标题路径；工作经历尽量保持公司+职位+时间+职责同块。
4. BGE 向量化 → ES `resume_vec`；resume 服务校验版本后写入/更新。
5. LLM 结构化抽取 → Schema 校验 → 低置信字段标“待人工确认” → MySQL。
6. kNN 自查去重 → 只提示，人工确认合并；保留旧版本。

### 6.4 ES 索引

- 索引 `resume_vec`：512 维（bge-small-zh-v1.5），`doc_type=resume|jd`；`emb_model` 版本字段。
- HNSW 参数必须在 `index_options`：

```json
"embedding": {
  "type": "dense_vector",
  "dims": 512,
  "index": true,
  "similarity": "cosine",
  "index_options": { "type": "hnsw", "m": 16, "ef_construction": 200 }
}
```

- 混合检索：`multi_match` BM25 + `knn` + RRF；保存检索参数/模型版本/人工反馈。
- 切换 BGE-M3（1024 维）时新建索引 + 别名切换，不混存不同维度。

### 6.5 人岗匹配

```
规则硬过滤（学历/年限/地点） → 混合召回 top50 → LLM 精排 top20
→ final = 0.3×召回分 + 0.7×LLM 分
```

- 五维：技能/经验/学历/稳定性/潜力；每维给证据；必备条件未命中封顶。
- 缓存键：job/resume 版本 + prompt 版本 + model；结果可解释、可覆盖。

### 6.6 纪要与异步评分

- 纪要触发：`room.finished` + 转写就绪；录像可选；无转写时 `INSUFFICIENT_TRANSCRIPT`。
- 输出：摘要、关键问答、证据引用、维度建议分、风险/待确认；面试官确认后才归档。
- 异步面试：逐题 ASR + 相关性/结构/深度/表达/专业性评分；人工复核可覆盖。

## 7. ASR 与在线面试

### 7.1 ASR WSS

- 令牌：room-service 签发 `scope=asr` 5 分钟 JWT（room/user/role）；浏览器连接
  `WSS /api/ai/v1/asr/{sessionId}?token=...`；Nginx rewrite 到 ai-worker `/ws/asr/{sessionId}`。
- 音频：每位参会人浏览器本地麦克风，16kHz/16bit/单声道 PCM，100~200ms/帧；1v5=6 路，1v1=2 路；不抓 LiveKit 混音轨。
- 协议：

```json
{"type":"start","roomId":"...","role":"CANDIDATE","sampleRate":16000,"channels":1}
// 二进制 Int16LE PCM 帧
{"type":"stop"}
// 服务端
{"type":"partial","text":"...","startMs":12000,"endMs":14500}
{"type":"final","segmentId":"...","text":"...","startMs":12000,"endMs":15000,"confidence":0.91}
{"type":"error","code":"ASR_OVERLOAD","message":"转写繁忙，已暂停实时字幕"}
```

- partial 不落库；final 经 ai-service → room-service 写 `transcript_segment`，按 `(room_id,speaker_id,segment_no)` 幂等；断线重连带 `lastSegmentId`。

### 7.2 容量契约

| 场景 | 音频流 | 实时字幕 |
|---|---:|---|
| 1×1v1 | 2 | 全量 |
| 1×1v5 | 6 | 全量 |
| 冒烟 2×1v1+1×1v5 | 10 | 全量 |
| 基线 5×1v1+5×1v5 | 40 | 前 20 路；其余降级 |
| 扩展 10+10 | 80 | 前 20 路；其余降级 |

- 单 ai-worker 目标 ≥20 路；多实例水平扩展；W1 压测校准。
- 超限 `ASR_OVERLOAD`：暂停实时字幕、会后补转写；面试/录制/评价不阻断。
- 要求基线全量实时 → 扩容并重测，不能沿用 20 路目标。

### 7.3 房间与录制

- 状态：`CREATED → WAITING → LIVE → FINISHED`（异常 `CANCELED/FAILED`）；1v1 上限 2，1v5 上限 6。
- 入会：`POST /api/room/rooms/{roomNo}/token`；校验登录、时间窗、名单、状态、名额；LiveKit token 只授指定 room+identity+能力。
- 信令：优先 `livekit.<domain>`；同域 `/livekit` 必须 rewrite 到 `/rtc`；UDP 直暴露。
- 录制：Egress 合成 MP4 → MinIO；`record_meta` 记录；失败不阻塞面试，可重试；回放需鉴权；保留 90 天。
- 笔记：`interview_note` 支持实时记录/编辑/查询；AI 纪要只作补充。
- 聊天：`chat_message` 落库后广播；支持离线拉取。
- 防作弊：`cheat_event` 只采集展示，不自动判定；人脸/虚拟背景/白板按 P2 处理。

## 9. 部署与验收

### 9.1 部署

- Compose：`base.yml`（Nacos/MySQL/Redis/RabbitMQ/ES/MinIO）+ `app.yml`（7 Java + ai-service + workers + LiveKit/Egress + Nginx）+ `gpu.yml`（vLLM）。
- 端口：仅 Nginx 80/443 公网；LiveKit 7880/7881 + UDP 50000-50100；管理/DB/ES/MinIO/vLLM 内网。
- 硬件：应用节点 16C64G 推荐（最低 32GB）+ GPU 节点 24GB；ES 堆 2~4G；Egress 录制单独计 CPU/带宽。
- 密钥：Nacos 加密/环境变量；`.env` 不入库；演示数据全部虚构。

### 9.2 验收

| 项 | 口径 |
|---|---|
| 鉴权 | 五角色；越权/隐藏按钮直调/禁用用户/取消授权全部 403/401 |
| 面试流程 | 申请→一面→评价→下一阶段；三方冲突拦截；Offer 确认 |
| 简历 | PDF/Word/图片各 ≥3 份，≥9 成解析；表格保留行列；失败可重试；重复合并 |
| 匹配 | Top5 命中率 ≥80%；F1 ≥85%；消融对比 |
| 在线面试 | 2×1v1+1×1v5 稳定 10 分钟；未邀请/超员被拒；断线重连 |
| 录制 | 结束后 ≤2 分钟可回放；鉴权；失败可重试 |
| 实时字幕 | 冒烟 10 路全量；基线 40 路按 20 路契约 |
| AI 故障 | 停 ai-worker/vLLM/ES，主业务继续；任务排队/可重试 |
| 容量 | HTTP P95 <300~500ms；WebRTC 基线 5+5；扩展 10+10 如实报告 |
